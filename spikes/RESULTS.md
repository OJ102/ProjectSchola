### Cost
- **A, vision:**
  - Measured headless cost is $0.07–0.09 per image. Most of that is Claude Code's own ~50k-token cached context per `claude -p` call; the image itself is about 1.5–2k tokens (w×h/750).
  - In the pipeline, the vision call should go through a small dedicated agent that batches several assets per call (≤20 images per Read limit).
  - The cost is lazy: *AI Engineering* has about 229 figures × ~2k ≈ 460k tokens if every figure were described. About 5 figures per unit means ~10k tokens per unit, paid once and cached in `vision/`.
- **B, Docling:**
  - 1.4 GB venv (`.spike-venv`, which includes rapidocr's ONNX models under `site-packages/rapidocr/models/`). **Correction:** I earlier reported 593 MB of new models in `~/.cache/huggingface`. File birth times show those models were already there from 2026-06-24, before this spike; Docling reused them and only updated directory mtimes. The paths are `~/.cache/huggingface/hub/models--docling-project--docling-layout-heron` (164 MB) and `~/.cache/huggingface/hub/models--docling-project--docling-models` (342 MB), plus their `.locks/` entries. **This spike created no new files outside `.spike-venv`.**
  - 6–34 s CPU per page after an 80 s cold start.
  - Formula decoding needs the separate CodeFormula model, not tested (another large download; ask before installing).
- **D and tesseract:** free, local, under 1.5 s per page.

### Recommendation: choose the default per segment kind
| Segment kind | Default | Fallback |
|---|---|---|
| text-layer prose (born-digital) | no OCR: text layer | – |
| scanned prose | **Apple Vision** (macOS, free, 0.8 s, robust on low-contrast and coloured backgrounds) | tesseract (non-macOS); `--ocr vision` on request |
| math, equations, slides with math, board keyframes | **Claude vision → LaTeX** | none viable locally (Docling without CodeFormula can't decode formulas) |
| charts and diagrams | **Claude vision** (the only method that gives data, structure and takeaway) | caption + surrounding text only |
| tables (image-only) | **Claude vision** | Docling, if it's ever installed for table-heavy scans |
| page-label strips on scans | tesseract at 150 dpi (see 0b) | Apple Vision |

**Docling isn't worth adopting now.** On this set it never beat Claude vision on fidelity, and it beat the local OCRs only on table structure. It costs ~2 GB and is slow on CPU. Keep it optional and unrecommended.

### Open risks
- The scan sample is simulated and mild. A real low-quality archive.org scan (skew, bleed-through, two columns) is still untested; the 0b strip OCR shows tesseract breaking on upsampled low-ppi images.
- No real video keyframe or handwriting was tested (no yt-dlp this round). The board sample is typeset LaTeX, which is easier than real chalk.
- Vision numbers read from charts are approximate. Briefs must present them as "about", and the figure description should be cited to the caption span, not treated as source text.

### Fixtures
- `book-labels.pdf` (hyperref `/PageLabels`) and `book-nolabels.pdf` (none): roman front matter i–iii, footer-less chapter openers, a footer-less blank page and **one page whose footer lies ("99")**.
- No-dictionary path result: i, ii, iii, 1, 2, 3, **4 (corrected from 99)**, 5, 6 with sources interpolated/footer/corrected. The chapter opener between the roman and arabic runs is labelled `1`, not `iv`, because arabic extrapolation wins wherever it gives ≥ 1.
- EPUB (pandoc, with `epub:type="pagebreak"` markers): locators like `Chapter Two: Currents § Thermohaline Circulation ¶3`, plus publisher page `3`; outline from `nav.xhtml`.
- VTT: span ids `tHH:MM:SS` (with `.2` suffix on same-second collisions), `&t=Ns` links, chapters from the NOTE line.

### Finding: poppler 26.04 crash
`pdftotext -bbox` / `-bbox-layout` aborts (`std::out_of_range`, exit 134) on any PDF whose Info dictionary holds an empty string, which is hyperref's default, so most LaTeX papers hit it. `locators.py` falls back to `pdftohtml -xml` and rebuilds blocks from line geometry and font ids. Both fixtures exercise that fallback. Increment 1 must keep this fallback and test it.

### Recommendation
- Adopt the precedence as planned: `/PageLabels` (via `pdfmini.py`, no qpdf needed) → footer regex → monotonic fit → interpolation → fallback. Keep running the footer fit even when the dictionary exists and report disagreement; it costs nothing and catches lying dictionaries.
- Span = one `-bbox-layout` block (one paragraph, list item, caption or footnote). Span id `p<pdf-index 4d>.<n>` keyed on the PDF index, not the printed label, so ids never collide on duplicate labels.
- Band-based header/footer stripping (top/bottom 8%) worked with no repeated-line statistics needed for this book. Keep the >30% repeated-line rule as a second pass for books whose running heads sit outside the band.

### Open risks
- Paragraphs that cross a page break become two spans; an anchor spanning both fails verification. The librarian prompt must say anchors stay inside one span.
- Inline footnote markers survive as " 21" inside span text ("conversations. 21 If you"). Anchors that cross them fail. Increment 1 should strip superscript markers (smaller font in the bbox/xml data).
- Math loses superscripts in the text layer (`E = mc (2.1)`); math pages need vision (0a).
- The roman/arabic boundary rule assumes body numbering starts at 1; per-chapter numbering ("3-14") is not handled yet.
- VTT rolling auto-captions are deduped only on exact repeats; real YouTube auto-subs need prefix-overlap merging.

### 0b revision after the design review (decisions 3, 4, 5, 10)
- `pdfmini.py` fails closed (decision 10). It caps the input at 512 MB, objects at 2M, nesting/tree depth at 100, pages at 100k, inflated streams at 64 MB and wall time at 30 s. EOF inside an array, dict or string raises `PDFError`. `/Root` is read only from a real `trailer` dict or `/XRef` stream. Label ranges keep their page offsets (`None` before the first range). `/St` that is ≤0 or >100000 leaves its pages unlabeled. `locators.py` catches `PDFError` and continues with the footer fit and no outline. All 10 adversary pdfmini cases now return in under 0.1 s with a clean result or a clean error.
- `pagelabels.py` (new), decisions 4 and 5:
  - **Candidates:** taken only from the outer 3 visual lines (bottom side first), in anchored shapes: bare, `N | head`, `head | N` (with `|`, `•`, `·` or em dash; Computer Modern renders `|` as an em dash), `Page N`, or `N head` where head repeats on ≥30% of pages in a ±15 page window. The outermost matching line wins. Every label on that line is a candidate, so `50 | head … head | 51` lets the fit choose.
  - **Labels:** strings in arabic, roman (≤400, valid, needs a neighbour) or chapter-prefixed (`3-14`, `A-1`) schemes.
  - **Fit:** runs of (scheme, offset). A sandwiched outlier is corrected and flagged. A lone arabic or roman point is dropped (the back cover's `57999` price code). Gaps take the next run extrapolated back when that gives ≥1, else the previous run forward.
  - **Short sources:** under 20 pages, any correction or ≤60% coverage gives PDF-index labels.
  - **Exclusions:** bare numbers are ignored on TOC pages (outline range) and on number-dense pages.
- **/PageLabels cross-check** (decision 3): more than 2% disagreement on footered pages means the footers win and `label_conflict` is written to `labels.json`. AI Engineering: 519 checked, 0 disagree, so the dictionary is used.
- **Multimap** (decision 4): `labels.json` holds `label_to_pdf`. Cross-refs resolve through it, picking the page that holds the referenced title. The renderer adds the section, or "PDF p. N", to labels that occur more than once: `p. ii (PDF p. 15)`.
- **Scanned pages:** pages with no text layer get only their top and bottom 13% strips rendered at 150 dpi and run through tesseract. 300 dpi fails on 60-ppi scans because tesseract misreads the upsampled glyphs ("Ll1" for "181").
- **Adversary label fixtures** (`adversarial/source-mode/fixtures`): 8 of 11 match the truth (chaptitle, clean_for_scan, pagelabels_disagree with `label_conflict`, perchapter, romanswitch with duplicate i–iii, romanwords, twocol, twonumbers). The other 3 differ by design:
  - lying and sparse: under 20 pages with ambiguous footers, so PDF-index labels.
  - scanned: OCR reads all 12 footers, 181–192. The fixture's blank first page is interpolated as 180; the .truth file omits that page.
- **AI Engineering after the revision:** PDF 102 = 78, PDF 73 = 49, outline 182, xrefs 33/33, sample 10/10, about 7 s total.

The first VTT run leaked 41 forgeries. With the plain 0.9 ratio over prev+cur+next cues, one swapped word, the neighbour's id and cross-cue joins all passed. Fixes now in `fuzzy()`:
- (decision 2) negations, numbers, units and comparatives must match exactly;
- substituted words must be spelled alike (char ratio ≥ 0.6), and inserted or dropped words must be stopwords or fillers;
- more than half of the matched window must lie inside the cited cue (decision 1: a match in a different span doesn't count).

Decision 1's floor (≥6 words or ≥30 chars, or the whole short span, and not stopwords only) and the self-written-locator rule are in `check_cite()`.

### Recommendations
- Keep the librarian tool-restricted. The headless probe confirms the agent only sees Read, Grep and Glob. A script writes and caches the brief (decision 6).
- One retry fixes everything seen so far. Both first-attempt failures were "invented a span id just past the unit end" and "wrote a timestamp itself". The retry prompt lists the checker's reasons and resumes the same session.
- **Small sources:** the 154-token lecture produced an 864-token brief, so the brief cost more than the source. Below about 1.5k source tokens, pass the unit lines themselves to the tutor and skip the brief (fast path, rule 5).
- Brief size sits well inside the 3k budget (0.9–2.4k).

### Open risks
- Paraphrase fidelity isn't proven by verification (see above); the `--strict` fact-checker is still unmeasured.
- Fuzzy mode was tested only on a hand-written VTT. Real auto-captions (rolling duplicates, no punctuation) are unmeasured until a yt-dlp source is allowed.
- Librarian cost is about $0.08 per clean unit and about $0.21 with a retry; a 10-chapter book (~60 units) costs about $5–8 to brief fully. Briefs are lazy (on first teach), so the cost is spread out.

### Findings that change the design
1. **Grep lookups must return span ids.** In the first run, segments stored `<!-- id -->` on a separate line, so a Grep hit had no id. The tutor guessed the neighbouring brief id and rendered "p. 79" for a sentence on p. 78. Segments now hold one span per line, `[p0102.7] text`. On the rerun, the lookup cited correctly (p. 78).
2. **Tutor cites need a quote check, not just an id allow-list.** The real run had no mis-quote (see the correction above), but the id allow-list alone can't catch one, and tester's crafted replies show the gap. The Stop-hook check (`source-cite-check.sh`) should:
   - verify any quotation placed right before a cite against the cited span;
   - re-point it deterministically when the quote is found in another span of the unit or the lookup set;
   - otherwise strip it.
   This is prototyped in `dryrun.py`.
3. With brief-only teaching, a full unit uses about 25% of the 10k budget. Two units per session plus a few lookups fit, which supports the plan's "/clear after about 2 units".

### Open risks
- Measured over 5 turns, not 40. Source-derived tokens grow only with lookups (about 100 tokens each), so the budget is safe. Total context grows with the conversation as usual.
- The tutor put a quotation mark around a paraphrase once, which the quote check flags. The skill should say that quotation marks mean verbatim.

### Fetch guardrails (decision 7), verified live
- Refused: `http://localhost/`, `http://169.254.169.254/…`, `file:///etc/passwd`, `http://127.0.0.1.nip.io/` (public DNS name resolving to loopback), and an httpbin redirect to `http://127.0.0.1/`, which is re-checked at the hop.

### Recommendations
- Use the stdlib heuristic as the default; no Docling or readability dependency is needed for articles. Apply the `NEG` rule on element ids unconditionally (a `class="section text-…"` once rescued dev.to's comments).
- Headings without ids get `URL § heading` locators (plan). Sphinx-style `section[id]` ids are moved onto the heading.
- A 403/429 from a bot wall (Medium) is a fetch failure, not an extraction failure. Report it and offer the WebFetch fallback marked `lossy`.
- Span storage neutralizes literal `[[` / `]]` for every source type, code blocks included (`srcnorm.neutralize`, inserting U+2060). This is part of the adapter contract. The verifier also rejects anchors containing `[[`.

### Open risks
- Byline and meta lines leak a few words on WordPress and Substack; harmless for teaching, but they become spans. A post-filter for short spans at the top (date/author patterns) would remove them.
- Paywalled teasers (Substack paid posts) would extract the teaser as if it were the article. Detect a `paywall` class or a "subscribe to read" marker and report it (untested; no paid post available).

### 0c gate (`spikes/source_verify.py`, `spikes/srcnorm.py`)
- **Decision 13:** anchors match as normalized *token sequences* (`srcnorm.find_tokens`), so "12 percent" doesn't match inside "112 percent", "safe" inside "unsafe", or "ides" inside "Tides". Punctuation is its own token.
- **Decision 16:**

  - protected tokens must match exactly: negations (including n't), numbers, units, comparatives, multiplicatives (once/twice/thrice/double/half…) and likelihood/modal words (likely, may, must, always, often, rarely, all, some, only…);

- **Decision 17 (strict schema):**

  - `## Where` is a single line, generated by code (`--where` compares it).

Only verified items are kept, dropped lines are listed in `<unit>.verify.json`, and an uncited plain-paragraph claim is dropped, never kept.
